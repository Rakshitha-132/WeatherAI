# WeatherAI

A responsive, static weather dashboard with city search, optional browser location, a seven-day forecast, and forecast-based tips. It uses Open-Meteo for weather and city search, plus BigDataCloud to turn an explicitly shared device location into a nearby place name. No API key, server, build step, or JavaScript package install is required.

The “Weather insights” are simple, rule-based summaries of the forecast. They are not generated by an AI service.

## Run locally

Open `index.html`, or serve the project folder with any static web server. Browser location access generally requires HTTPS or localhost; use the deployed HTTPS address to test it.

## Publish with GitHub Pages

1. Push the project files to the `main` branch of a GitHub repository.
2. In the repository, open **Settings → Pages**.
3. Under **Build and deployment**, select **GitHub Actions** as the source.
4. Open the **Actions** tab and wait for **Deploy WeatherAI to GitHub Pages** to finish.
5. After the first successful deployment, open the Pages URL shown in the workflow or Pages settings.

The same files can be published by a static hosting provider such as Netlify or Cloudflare Pages. Use the repository root as the publish directory and leave the build command empty.

## Location and data

City searches are sent to Open-Meteo's geocoding service. Weather requests send the selected location's coordinates to Open-Meteo. If you choose **Use my location**, your browser asks for permission; the coordinates are then sent to Open-Meteo for weather and BigDataCloud for a nearby place name. The app does not save location history.

Weather and geocoding availability, limits, and terms are controlled by those providers. Review their current terms before using this project commercially.
